# Backend симулятора «Аким на 5 часов»

Backend принимает пять выбранных мероприятий, проверяет ограничения и рассчитывает **Astana Quality of Life Score**. Frontend получает готовую оценку, изменения по каждому району, использованный бюджет и объяснение результата на русском языке. Отдельные эндпоинты предоставляют справочники и геоданные для карты.

Этот файл описывает текущие контроллеры, модели ответов, правила и сохранённые данные проекта. Примеры предназначены для чтения и интеграции frontend.

## Общие правила API

Локальный адрес по умолчанию: `http://localhost:8080`.

| Свойство | Поведение |
|---|---|
| Основной префикс | `/api/v1` |
| Дополнительные адреса | Только `calculate` и `baseline` доступны также через `/api/simulation/...` |
| Формат обычного ответа | JSON, `Content-Type: application/json` |
| Формат геометрии | GeoJSON, `Content-Type: application/geo+json` |
| Формат ошибок приложения | Problem Details, `Content-Type: application/problem+json` |
| Тело POST | JSON с заголовком `Content-Type: application/json` |
| Параметры GET | У перечисленных GET нет тела и прикладных query-параметров; два маршрута используют `{id}` в пути |
| Авторизация | В текущем backend не реализована; токен для этих маршрутов не требуется |
| Пагинация и фильтры | Не реализованы; списки и географические слои возвращаются целиком |
| Сохранение сценариев | Не реализовано; POST возвращает результат без записи в БД |
| Повторный расчёт | Каждый запрос начинает с исходного датасета; эффекты прошлых запросов не накапливаются |
| LLM | Внешний LLM не вызывается; объяснение создаётся по шаблону из результата расчёта |

В таблицах ниже `number` — JSON-число, `integer` — целое JSON-число, `object<код, number>` — объект с кодами в качестве ключей. Например, `{"T1": 4.5, "T2": 6.75}`.

Коды районов в симуляции: `esil`, `almaty`, `saryarka`, `baikonur`, `nura`. Коды мероприятий: `M1`–`M14`. В POST коды регистрозависимы: передавайте `M7` и `nura`. В GET справочника районов `{id}` приводится к нижнему регистру, но пробелы не удаляются.

## Районы и показатели

### GET /api/v1/districts

**Назначение:** заполнить список районов, показать исходное состояние города, связать числовые показатели с полигонами карты.

**Запрос:** без параметров и тела. **Ответ:** `200`, массив из пяти объектов `DistrictResponse` в порядке `esil`, `almaty`, `saryarka`, `baikonur`, `nura`.

| Поле объекта | Тип | Значение и назначение |
|---|---|---|
| `id` | string | Код района; используется в POST и для связи с `properties.district_id` карты |
| `name` | string | Русское название для интерфейса |
| `populationShare` | number | Доля населения в модели; вес района при расчёте `D_avg` |
| `metrics` | object<код, integer> | Десять исходных индексов от 0 до 100 |
| `baselineScore` | number | Исходный балл **района** `D_d`, а не итоговый городской Score |

Пример одного элемента массива:

```json
{
  "id": "nura",
  "name": "Нура",
  "populationShare": 0.16,
  "metrics": {
    "T1": 55, "T2": 40,
    "E1": 45, "E2": 65,
    "S1": 38, "S2": 35,
    "B1": 55, "B2": 50,
    "C1": 60, "C2": 50
  },
  "baselineScore": 49.18
}
```

### GET /api/v1/districts/{id}

**Назначение:** получить данные только выбранного района. `{id}` — обязательный код района, например `nura`.

**Ответ:** `200`, один объект `DistrictResponse` с полями из таблицы выше, без массива. Если район не найден — `404` с Problem Details. Структура ошибки описана в разделе [Ошибки](#ошибки).

### Полный исходный датасет

| ID | Район | Доля населения | T1 | T2 | E1 | E2 | S1 | S2 | B1 | B2 | C1 | C2 | Балл района D |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| `esil` | Есиль | 0.27 | 45 | 62 | 68 | 72 | 48 | 55 | 78 | 60 | 75 | 70 | 62.99 |
| `almaty` | Алматы | 0.24 | 40 | 75 | 50 | 55 | 60 | 65 | 62 | 52 | 50 | 60 | 57.06 |
| `saryarka` | Сарыарка | 0.20 | 50 | 70 | 42 | 40 | 62 | 68 | 58 | 55 | 45 | 55 | 54.65 |
| `baikonur` | Байконур | 0.13 | 52 | 68 | 55 | 50 | 58 | 60 | 52 | 58 | 55 | 58 | 56.63 |
| `nura` | Нура | 0.16 | 55 | 40 | 45 | 65 | 38 | 35 | 55 | 50 | 60 | 50 | 49.18 |

Доли населения в сумме равны 1. Пять районов — состав конкурсной модели, а не утверждение об актуальном административном делении города.

### Что означают показатели

Все индексы направлены одинаково: **чем выше значение, тем лучше**. Например, увеличение `T1` означает уменьшение пробок.

| Код | Направление | Что измеряет | Вес в балле района |
|---|---|---|---:|
| `T1` | Транспорт | Разгрузка дорог | 0.10 |
| `T2` | Транспорт | Доступность общественного транспорта | 0.10 |
| `E1` | Экология | Озеленение | 0.09 |
| `E2` | Экология | Качество воздуха | 0.11 |
| `S1` | Соцсфера | Обеспеченность школами и детсадами | 0.11 |
| `S2` | Соцсфера | Поликлиники и первичная медицинская помощь | 0.11 |
| `B1` | Безопасность | Безопасность улиц | 0.09 |
| `B2` | Безопасность | Безопасность дорожного движения | 0.09 |
| `C1` | Сервисы | Надёжность ЖКХ | 0.10 |
| `C2` | Сервисы | Скорость решения обращений жителей | 0.10 |

## Мероприятия

### GET /api/v1/measures

**Назначение:** показать доступные решения, их стоимость, область действия и эффекты. **Запрос:** без параметров и тела. **Ответ:** `200`, массив из 14 объектов `MeasureResponse`, от `M1` до `M14`.

| Поле | Тип | Значение и назначение |
|---|---|---|
| `id` | string | ID меры, передаётся в `decisions[].measureId` |
| `categoryId` | string | Код направления; по нему проверяется лимит двух мер |
| `categoryName` | string | Название направления на русском |
| `name` | string | Название мероприятия |
| `scope` | string | `district` — один район; `city` — все пять районов |
| `cost` | integer | Стоимость в условных единицах; для городской меры платится один раз |
| `lagQuarters` | integer | Лаг до начала действия меры, в кварталах |
| `realizationFactor` | number | Доля реализованного эффекта: `(8 - lagQuarters) / 8` |
| `fullEffects` | object<код, integer> | Полные изменения индексов до учёта лага |
| `realizedEffects` | object<код, number> | Изменения после учёта лага, до синергий и ограничения диапазона |

В объектах эффектов перечислены только затрагиваемые показатели. Отсутствие кода означает нулевой эффект. Значения — прибавки к индексу, а не проценты от исходного значения.

```json
{
  "id": "M1",
  "categoryId": "transport",
  "categoryName": "Транспорт",
  "name": "Выделенные полосы для автобусов",
  "scope": "district",
  "cost": 18,
  "lagQuarters": 2,
  "realizationFactor": 0.75,
  "fullEffects": { "T1": 6, "T2": 9 },
  "realizedEffects": { "T1": 4.5, "T2": 6.75 }
}
```

### GET /api/v1/districts/{id}/measures

**Назначение:** показать мероприятия после выбора района на карте. `{id}` обязателен. Например, `/api/v1/districts/nura/measures`.

**Ответ:** `200`, массив из 14 объектов `DistrictMeasureResponse`. Каждый объект содержит **все поля `MeasureResponse`** и ещё два поля:

| Поле | Тип | Для районной меры | Для городской меры |
|---|---|---|---|
| `targetDistrictId` | string или null | Код района из URL | `null` |
| `affectedDistrictIds` | string[] | Один выбранный район | Все пять районов |

Для Нуры у `M1` будет `targetDistrictId: "nura"`, `affectedDistrictIds: ["nura"]`; у `M2` — `targetDistrictId: null`, `affectedDistrictIds: ["esil", "almaty", "saryarka", "baikonur", "nura"]`.

Этот эндпоинт не отбирает меры по текущему бюджету или ранее выбранным решениям: такой список ему не передаётся. Он также не применяет эффекты и не меняет датасет. Неизвестный район возвращает `404`.

## Начальные настройки симуляции

### GET /api/v1/simulation/bootstrap

**Назначение:** получить правила и адреса зависимых API одним запросом при открытии страницы. **Ответ:** `200`, объект `BootstrapResponse`.

| Поле | Тип | Значение или назначение |
|---|---|---|
| `apiVersion` | string | `v1` |
| `budgetLimit` | integer | `100` |
| `requiredDecisionCount` | integer | `5` |
| `horizonQuarters` | integer | `8` |
| `maxMeasuresPerCategory` | integer | `2` |
| `baselineScore` | number | Округлённый городской Score без действий: `52.56` |
| `api` | object | Ссылки на справочники, расчёт и документацию |
| `map` | object | Ссылки на шесть файлов карты |
| `dataNotes` | string[] | Пояснения о синтетическом датасете и назначении геоданных |
| `scoreRules` | object | Формула, веса, критический порог, синергии и конфликты |

Все поля `api` имеют тип `string`:

| Поле | Значение |
|---|---|
| `districts` | `/api/v1/districts` |
| `districtTemplate` | `/api/v1/districts/{districtId}` |
| `measures` | `/api/v1/measures` |
| `districtMeasuresTemplate` | `/api/v1/districts/{districtId}/measures` |
| `mapLayers` | `/api/v1/map/layers` |
| `calculate` | `/api/v1/simulation/calculate` |
| `baseline` | `/api/v1/simulation/baseline` |
| `swaggerUi` | `/swagger-ui.html` |
| `openApi` | `/v3/api-docs` |

В шаблонах замените `{districtId}` реальным кодом. В декларации контроллера тот же параметр называется `{id}` — это один сегмент URL.

Все поля `map` также имеют тип `string`:

| Поле | Значение |
|---|---|
| `cityBoundary` | `/api/v1/map/city-boundary` |
| `districts` | `/api/v1/map/districts` |
| `districtStats` | `/api/v1/map/district-stats` |
| `pois` | `/api/v1/map/pois` |
| `parks` | `/api/v1/map/parks` |
| `roads` | `/api/v1/map/roads` |

Поля `scoreRules`:

| Поле | Тип | Назначение |
|---|---|---|
| `formula` | string | `0.7 * D_avg + 0.3 * D_min - N_crit` |
| `metricWeights` | object<код, number> | Все десять весов из таблицы показателей |
| `criticalThresholdExclusive` | number | `40`; критическим считается значение строго ниже порога |
| `synergies` | object[] | Три правила дополнительных бонусов |
| `conflicts` | object[] | Три правила несовместимости |

Каждый объект `scoreRules.synergies[]`:

| Поле | Тип | Назначение |
|---|---|---|
| `districtMeasureId` | string | Районная мера пары; определяет район бонуса |
| `cityMeasureId` | string | Городская мера пары |
| `metric` | string | Код показателя, получающего бонус |
| `bonus` | integer | Прибавка к показателю, сейчас `2` |

Каждый объект `scoreRules.conflicts[]`:

| Поле | Тип | Назначение |
|---|---|---|
| `firstMeasureId` | string | Первая несовместимая мера |
| `secondMeasureId` | string | Вторая несовместимая мера |
| `sameDistrictOnly` | boolean | `true` — запрет только в одном районе; `false` — запрет независимо от районов |
| `reason` | string | Русское объяснение конфликта |

Значения всех синергий и конфликтов приведены в разделе [Формула и ограничения](#формула-и-ограничения).

## Расчёт сценария

### POST /api/v1/simulation/calculate

Дополнительный равнозначный адрес: `POST /api/simulation/calculate`.

**Назначение:** отправить готовый набор решений и получить итоговую оценку. Параметров URL нет. Заголовок: `Content-Type: application/json`.

### Тело запроса

| Поле | Тип | Обязательность и смысл |
|---|---|---|
| `decisions` | object[] | Обязательно; ровно 5 объектов |
| `decisions[].measureId` | string | Обязательно; ID существующего мероприятия |
| `decisions[].districtId` | string или null | Для `district` обязателен существующий район; для `city` поле отсутствует либо равно `null` |

Для городской меры нельзя передавать `"city"`, пустую строку или код района в `districtId`. Пустая строка не равнозначна `null`.

Frontend передаёт только выбор мероприятий и районов. Стоимость, эффекты, бюджет, горизонт и веса backend берёт из своего каталога и правил.

Пример из [simulation-example.json](docs1/simulation-example.json):

```json
{
  "decisions": [
    { "measureId": "M7", "districtId": "nura" },
    { "measureId": "M8", "districtId": "nura" },
    { "measureId": "M10", "districtId": "nura" },
    { "measureId": "M12" },
    { "measureId": "M5", "districtId": "saryarka" }
  ]
}
```

**Успех:** `200`, объект `SimulationResult`. **Нарушение правил:** `422`, причины без Score. **Некорректное тело запроса:** `400`.

## Формула и ограничения

### Условия допустимого сценария

1. Ровно пять решений.
2. Общая стоимость не больше 100; ровно 100 допустимо.
3. Каждая мера выбирается максимум один раз, даже если районы разные.
4. Не больше двух мер одного направления. Выбирать по одной из каждого направления не обязательно.
5. Для районной меры выбран существующий район, для городской район не указан.
6. Нет несовместимых сочетаний.

Остаток бюджета не даёт бонуса. Городская мера занимает одно из пяти решений и оплачивается один раз. Порядок выбора не влияет на вычисления.

### Синергии

| Пара | Дополнительный эффект | Где применяется |
|---|---|---|
| M1 + M2 | T1 +2 | В районе M1 |
| M10 + M12 | B1 +2 | В районе M10 |
| M5 + M6 | E2 +2 | В районе M5 |

Бонус возникает, только если выбраны обе меры. Он фиксированный и не умножается на долю реализации эффекта.

### Конфликты

| Пара | Область запрета | Причина |
|---|---|---|
| M1 + M3 | Любые районы | Либо BRT, либо ЛРТ |
| M4 + M7 | Только один и тот же район | Конфликт за участок |
| M5 + M13 | Только один и тот же район | Дублирование программы |

M4 и M7 в разных районах разрешены. То же относится к M5 и M13. M1 и M3 нельзя выбрать вместе даже в разных районах.

### Порядок вычислений

Обозначения: `d` — район, `k` — показатель, `m` — выбранная мера, `L_m` — лаг меры, `pop_d` — доля населения района, `w_k` — вес показателя.

```text
H = 8
realizationFactor_m = (8 - L_m) / 8

I'_dk = clip(I_dk + Σ(fullEffect_mk × realizationFactor_m) + synergy_dk, 0, 100)

D_d = Σ(w_k × I'_dk)
D_avg = Σ(pop_d × D_d)
D_min = min(D_d)
N_crit = количество пар (d, k), где I'_dk < 40

FINAL SCORE = 0.7 × D_avg + 0.3 × D_min - 1 × N_crit
```

Сумма эффектов включает только меры, затрагивающие данный район. Сначала складываются все эффекты и синергии, затем применяется `clip`: ниже 0 становится 0, выше 100 становится 100. Сам итоговый Score дополнительно не обрезается.

Порог критичности строгий: `39.99` ниже порога, `40` уже не критическое значение. Штраф считается после эффектов, синергий и clip.

Расчёт выполняется через `BigDecimal`, без промежуточного округления. Только `displayScore` и числа в объяснении округляются до двух знаков по `HALF_UP`. Исходные баллы районов калькулятор вычисляет по показателям, а не берёт из заранее записанного `DistrictResponse.baselineScore`.

## Ошибки

### HTTP 422 — невалидный сценарий

При нарушении правил `calculate` возвращает `application/problem+json`. У такого ответа нет `finalScore`, `summary` и результата симуляции.

```json
{
  "type": "about:blank",
  "title": "Невалидный сценарий",
  "status": 422,
  "detail": "Набор решений невалиден. Score не рассчитан.",
  "instance": "/api/simulation/calculate",
  "errors": [
    {
      "code": "DECISION_COUNT",
      "field": "decisions",
      "message": "Нужно выбрать ровно 5 мероприятий"
    }
  ]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `type` | string | URI типа ошибки; для текущих ошибок обычно `about:blank` |
| `title` | string | Краткое название |
| `status` | integer | HTTP-статус |
| `detail` | string | Общее объяснение |
| `instance` | string | Путь запроса, вызвавшего ошибку |
| `errors` | object[] | Детальные нарушения; расширение ответа именно для валидации сценария |
| `errors[].code` | string | Машинный код для логики frontend |
| `errors[].field` | string | Поле запроса, например `decisions[0].districtId`; индексы начинаются с 0 |
| `errors[].message` | string | Текст причины для пользователя |

Полный список кодов валидатора:

| code | Когда возникает | field |
|---|---|---|
| `DECISION_COUNT` | `decisions` отсутствует, равен null или содержит не 5 элементов | `decisions` |
| `MEASURE_REQUIRED` | Элемент массива null; `measureId` отсутствует, null или пустой | `decisions[i].measureId` |
| `UNKNOWN_MEASURE` | ID не найден в каталоге, включая неправильный регистр | `decisions[i].measureId` |
| `DUPLICATE_MEASURE` | Мера уже встречалась в наборе | `decisions[i].measureId` |
| `CITY_DISTRICT_FORBIDDEN` | Для городской меры передан ненулевой `districtId`, включая пустую строку | `decisions[i].districtId` |
| `DISTRICT_REQUIRED` | У районной меры район отсутствует, null или пустой | `decisions[i].districtId` |
| `UNKNOWN_DISTRICT` | Район районной меры не найден | `decisions[i].districtId` |
| `BUDGET_EXCEEDED` | Стоимость превышает 100 | `decisions` |
| `CATEGORY_LIMIT` | Более двух мер одного направления | `decisions` |
| `CONFLICT` | Найдена запрещённая пара | `decisions` |

При неправильном числе решений валидатор сразу возвращает `DECISION_COUNT`. Если элементов пять, он собирает нарушения дальнейших проверок; ошибок в одном ответе может быть несколько.

### Другие статусы

| Статус | Где возникает | Причина |
|---|---|---|
| `400` | POST calculate | Повреждённый JSON, отсутствующее тело, тело `null` или несовместимая структура JSON |
| `404` | GET districts/{id}, GET districts/{id}/measures | Неизвестный район |
| `405` | Неподдерживаемый метод для существующего маршрута | Например, попытка POST к справочнику |
| `415` | POST calculate | Неподдерживаемый тип содержимого запроса |
| `500` | Чтение слоя карты или манифеста слоёв | Файл отсутствует в classpath либо не может быть прочитан |

Пример содержимого `detail` при неизвестном районе: `Район с id 'unknown' не найден`. Для отсутствующего файла карты: `Map resource is missing: map-data/astana/имя_файла`.

У стандартных ошибок Spring нет обязательного массива `errors`. Frontend должен сначала проверить HTTP-статус, затем использовать `errors`, если он есть, иначе `detail` или `title`.

| `type` | string | `FeatureCollection` |
| `features` | object[] | Географические объекты |
| `features[].type` | string | `Feature` |
| `features[].geometry` | object | Геометрия объекта |
| `features[].geometry.type` | string | Point, LineString, Polygon или MultiPolygon в зависимости от слоя |
| `features[].geometry.coordinates` | array | Координаты соответствующей вложенности |
| `features[].properties` | object | Атрибуты объекта; различаются по слоям |

Координаты заданы как `[долгота, широта]`, в градусах WGS84. Для `Point` это одна пара, для `LineString` — массив пар, для `Polygon` — массив колец, для `MultiPolygon` — массив полигонов. Координаты передаются целиком, их не нужно преобразовывать в индексы симуляции.

Ответы шести файлов карты имеют `Content-Length` и `Cache-Control` с `public` и `max-age=3600`. Контроллер передаёт содержимое подготовленного файла без фильтрации и пересчёта; `MapDataService` кеширует прочитанные байты в памяти процесса. Заголовок кеширования не задан отдельно для `/map/layers`.

**Назначение:** нарисовать пять районов и обрабатывать выбор полигона. **Ответ:** `200`, GeoJSON, 5 объектов; геометрия `Polygon` или `MultiPolygon`.

## Swagger и OpenAPI

`GET /swagger-ui.html` перенаправляет на HTML-интерфейс `/swagger-ui/index.html`. В нём отображаются операции и модели, а у POST calculate задан готовый пример из конкурсного датасета.

`GET /v3/api-docs` возвращает JSON-схему OpenAPI; `/v3/api-docs.yaml` — её YAML-представление. Они генерируются по контроллерам, Java-моделям и аннотациям. Сохранённая схема [docs1/openapi.yaml](docs1/openapi.yaml) имеет версию OpenAPI `3.1.0`; версия прикладного API указана в `info.version` как `v1`.

Основные разделы схемы:

| Поле | Что содержит |
|---|---|
| `openapi` | Версию формата OpenAPI |
| `info` | Название, описание и версию прикладного API |
| `servers` | Адрес сервера; в сохранённом экспорте — localhost:8080 |
| `tags` | Группы операций, включая `Simulation` |
| `paths` | Пути, HTTP-методы, параметры, тела запросов, примеры и ответы |
| `components.schemas` | Модели запросов и ответов, на которые ссылаются операции |

Экспорт — снимок схемы, он не обновляется при редактировании Java-файлов. Поля сырых GeoJSON/JSON-файлов подробнее описаны в этом README: контроллер отдаёт их как байты, поэтому автоматически сгенерированная схема не раскрывает их бизнес-структуру полностью.

## Как frontend использует API

1. Получает `bootstrap`: лимит бюджета, количество решений, правила и ссылки.
2. Загружает `districts` и `measures` для исходных карточек и списка решений.
3. Загружает границу города и полигоны районов. Связывает их с каталогом по `district_id` и `id`.
4. По выбору района использует `/districts/{id}/measures`, чтобы показать область действия каждой меры.
5. Хранит выбранные решения на клиенте; для городской меры не отправляет `districtId`.
6. Отправляет пять решений в `calculate`.
7. При `422` показывает `errors[].message`, выделяя `errors[].field`. При `200` выводит итог и обновляет показатели на карте.
8. Загружает POI, парки и дороги по включению соответствующих слоёв. Фильтрует крупные слои на клиенте.

| Элемент интерфейса | Источник данных |
|---|---|
| Итоговая карточка или карточка для публикации | `metricName`, `displayScore` |
| Прирост относительно базы | `scoreDelta`, отформатированный до нужной точности |
| Полоса бюджета | `budget.spent`, `budget.limit`, `budget.remaining` |
| Общая оценка города | `summary.dAvg` |
| Самый слабый район | `summary.weakestDistrictName`, `summary.dMin` |
| Проблемные показатели | `summary.criticalMetrics` |
| Цвет района после расчёта | `districts[].scoreAfter` |
| Изменение цвета или подпись улучшения | `districts[].scoreDelta` |
| Таблица показателей до/после | `districts[].before`, `after`, `metricDeltas` |
| Список выбранных мер и задержек | `measureEffects` |
| Бонусы сочетаний | `synergies` |
| Объяснение, сильные стороны, риски | `explanation` |

Frontend может заранее проверять ограничения для удобства пользователя, но окончательное решение о валидности принимает backend. Числа итогового Score следует брать из ответа API.

## Настройки и расположение данных

Стек текущего проекта: Java 21, Spring Boot 4.1.1, Spring Web MVC, springdoc-openapi 3.0.3. В `pom.xml` присутствуют JPA/JDBC и драйвер PostgreSQL, но автоконфигурация datasource и Hibernate отключена: нынешние справочники и расчёты работают без БД.

Для новой сборки с геоданными эти пути должны быть согласованы. В уже собранном приложении файлы читаются из classpath `map-data/astana/`; напрямую каталог `data1` сервер не читает.

В сборку включаются `city_boundary.geojson`, `district_stats.json`, `districts.geojson`, `parks.geojson`, `pois.geojson`, `roads_main.geojson`. CSV статистики и исходные Parquet-файлы не включены в эти API.

Каталог индексов и мер задан в Java-коде, поэтому изменение Word-документа само по себе не меняет расчёт. При изменении модели необходимо согласованно обновлять `CatalogService`, `SimulationRules`, версию модели и описание API. Геоданные остаются отдельным источником пространственного контекста.
