# Карта Астаны (Overture Maps)

Источник: [Overture Maps Foundation](https://overturemaps.org), релиз `2026-08-19.0`, bbox `71.20,50.98,71.75,51.30`.
Пересобрать: `pip install overturemaps duckdb && python scripts/overture_astana.py`
(только обработка без скачивания: `--skip-download`).

## Файлы

| Файл | Что внутри |
|---|---|
| `districts.geojson` | Границы 6 районов. `district_id`: `esil`, `almaty`, `saryarka`, `baikonur`, `nura`, `saraishyk`. У каждого полигона есть исходные идентификаторы Overture/OSM |
| `city_boundary.geojson` | Граница города |
| `district_stats.json` / `.csv` | Статистика по районам: площадь, здания, школы, детсады, больницы, поликлиники, остановки, светофоры, переходы, фонари, парки и зелень (км²), дороги (км по классам) |
| `pois.geojson` | Точки с полями `kind` (school, kindergarten, hospital, clinic, bus_stop, traffic_signals, crossing, street_lamp) и `district_id` |
| `parks.geojson` | Полигоны парков и скверов |
| `roads_main.geojson` | Магистрали (trunk, primary, secondary, tertiary) и ЛРТ |
| `lrt.geojson` | Отдельный слой M3: 31 существующий сегмент `light_rail` из `roads_main.geojson`, с исходными координатами, атрибуцией и оговоркой о неполноте |
| `raw/*.parquet` | Сырые слои Overture в формате GeoParquet: building (124k), segment, connector, place (8.3k), land_use, land_cover, water, infrastructure, division* |

## Оговорки

Слой ЛРТ пересобирается без внешних зависимостей командой `python scripts/prepare_lrt.py`;
`scripts/overture_astana.py` также обновляет его и скачивает фиксированный релиз `2026-08-19.0`.
Это частичная геометрия, а не вся линия: станции отсутствуют, разрывы не соединяются.
`metadata.geometry_length_km` — приближённая сумма длин исходных сегментов по формуле haversine
(48,247 км для текущих 31 сегмента); она может включать параллельные пути и не равна официальной длине линии.
27 сегментов этой выгрузки отнесены к Есилю, 4 — к Сарайшыку; это не доказывает отсутствие ЛРТ в других районах.
Официальные сведения о проекте и их источники хранятся отдельно от геометрии.

- Данные собраны из OSM и других открытых источников, поэтому они неполные. Их можно использовать для карты и
  как ориентир, но это не официальная статистика. Индексы 0–100 в симуляторе берутся из синтетического датасета.
- Сарайшык включён по настоящему полигону `Сарайшық ауданы`, который источник классифицирует как `locality`:
  Overture `b367ecc9-9ec4-4cc0-a73c-b7e3cea38787`, [OSM relation 19733918](https://www.openstreetmap.org/relation/19733918),
  версия `r19733918@12` от `2026-07-16`. Площадь геометрии — 61,4 км²; синтетической границы нет.
  В этой выгрузке Алматы уже отделён от Сарайшыка. Внутренности всех шести полигонов не пересекаются.
  Скрипт проверяет пересечения до расчёта статистики и прекращает обработку при конфликте границ.
- Отдельная граница города в источнике занимает 800,228 км², союз шести районов — 789,195 км².
  Оставшиеся 11,033 км² не приписаны району в исходной геометрии. Эта территория не дорисовывается
  и не распределяется искусственно; расхождение записано в `metadata.city_area_without_district_km2`
  коллекций границ. Выходов районов за границу города нет.
- Объект относится к району по `ST_Within`: центроид для площадных объектов и `ST_PointOnSurface` для дорог.
  Длины целых сегментов и площади целых объектов не обрезаются границей района. Это приблизительная
  пространственная группировка объектов источника, а не официальная статистика инфраструктуры.
- Bbox покрывает 82,75% геометрии Есиля, 95,12% Алматы, 95,00% Байконура и 100% остальных трёх районов.
  Для частично покрытых районов числа объектов, зелёные площади и длины дорог неполны.
  Даже 100% покрытия bbox не гарантирует полноту OSM/Overture. В `district_stats` это явно отмечено полями
  `data_quality`, `observation_bbox_coverage_pct`, `coverage_note`, а происхождение границ — `boundary_source_*`.
- Коллекции POI, парков и магистралей содержат `metadata.input_feature_count` и
  `metadata.unassigned_input_feature_count`: исходные объекты вне полигонов или на их границах
  не распределяются между районами искусственно. Уникальность исходного `id` при экспорте проверяется.
